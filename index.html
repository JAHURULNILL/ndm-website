Install on Windows

Run NDM_2.0.10_x64-setup.exe. The install is per-user, with no administrator prompt, and it registers the browser bridge, so the extension can reach the app without manual setup. Launch NDM from the Start menu; uninstall through Settings, then Apps. The portable ZIP needs no install: extract it anywhere and run the app.

Install on Linux

Install the .deb with apt, so the dependencies come with it:

sudo apt install ./NDM_2.0.10_amd64.deb

Launch NDM from the applications menu.

Add the extension

The desktop app goes in first — the extension passes links to it through a native messaging host. Unzip ndm-extension-2.0.10.zip. In Chrome, Brave or Edge, open chrome://extensions, enable Developer mode, choose Load unpacked and select the unzipped folder. In Firefox, open about:debugging#/runtime/this-firefox, choose Load Temporary Add-on and select the manifest.json inside the folder; Firefox drops temporary add-ons at restart, so load it again the same way.

What’s new in 2.0.10

2.0.10 is a required update: copies older than this are asked to update once, and new downloads stay paused until it is installed. The prompt changes nothing else. The list and any partial files are exactly as they were.

Download Later keeps the download. The folder, timing and size chosen in the browser now travel with a “later” download through the extension and the native host. Before, the app opened its add dialog anyway, and closing that dialog threw the download away after the card had already said it was queued.

Cancel means cancelled. The browser card waits for the app’s answer now. If a cancel fails, the card restores its buttons and keeps watching, instead of reporting a success that never happened.

An interrupted merge is no longer a finish. A video whose merge was interrupted — by a power cut, say — restores as paused, and its file is verified when it resumes, instead of being marked Finished on its length alone.

Deleting waits; Pause All reaches everything. Deleting a download now waits for the engine to truly settle instead of racing it after five seconds, and Pause All also requeues downloads that are starting or merging, not only ones already running.

Videos start sooner. The format picked in the picker is warmed at pick time rather than resolved a second time at start, and resolving is bounded at 45 seconds with a working fallback, instead of an indefinite hang.

Smaller truths, swept clean. Finished downloads’ connection rows now read “Done”; the stale zero-byte .ndm.lock files are swept from the download folder; and a failed portable update relaunches the restored copy and leaves a note of the failure, instead of leaving nothing running.

System requirements — Windows

Windows 7 SP1, 8, 8.1, 10 or 11, 64-bit (x86-64). The installer runs per-user; nothing is installed system-wide, and the app carries its C runtime with it, so no separate redistributable is needed on any supported Windows.

On Windows 7 SP1, 8 and 8.1, the installer also provisions the WebView2 runtime in the background during setup: Microsoft’s pinned 109.0.1518.78 build, checked against its SHA-256 hash before it runs. There is nothing to click.

The installer is the app alone. On first launch the video components (yt-dlp, deno and ffmpeg) are downloaded once, in the background, into the app-data folder — each checked against a SHA-256 hash pinned in the app before it is allowed to run.

System requirements — Linux

A 64-bit Debian-family distribution: Debian, Ubuntu, Zorin OS, Linux Mint and derivatives. The .deb declares its dependencies — libwebkit2gtk-4.1-0, libgtk-3-0 and ffmpeg — and apt installs them with the package.

On first use, the video components (yt-dlp and deno, about 83 MB) are downloaded once into the app-data folder, each verified against a pinned SHA-256 hash before it runs.

NDM installs no background services and starts nothing at boot. The extension needs the desktop app installed: it passes links through a small bridge process the browser starts on demand.
