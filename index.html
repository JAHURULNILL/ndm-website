Progress has a place to return to.

NDM writes parallel file blocks to their final offsets and journals progress as it happens. A restart can continue from the recorded byte—without temporary part files or a later merge pass for a regular download.

  1. 01

    Divide the work.

    One file can use up to 32 connections, working in 1 MiB blocks.

  2. 02

    Write in place.

    Each block goes to its final position in the file instead of a temporary part file.

  3. 03

    Keep the record.

    Progress is journaled as it arrives, so an interrupted transfer can resume after the app or machine restarts.

Notes included with package set v2.3.2
  1. A download whose link expires in the middle no longer dies there. When the server answers a range with 403 or 410 — the signed address has lapsed — NDM re-resolves the address and resumes from the journal, for plain files and for browser-captured video alike. On the test rig, the two shapes that used to fail, at 44% and at 63%, now run to completion byte-identical. A paused download is never woken by the refresh, and if the file behind the link has changed, the entry restarts cleanly from zero instead of splicing two different files together.
  2. Facebook’s picker is instant now, finishing what the last release started. A video on Facebook fills the picker from the page’s own data, the way YouTube already did — quality rows at once, on posts, watch pages and the feed, each video on a busy page offered on its own. A video the page cannot identify is reported plainly, instead of the picker probing the wrong address; and if Facebook changes its page structure, the picker falls back to the classic resolver on its own.
  3. Connections that decay are recycled. Some servers hand each connection a fast burst and then clamp it to a trickle — the shape behind most “slower than the other manager” reports — and a download could sit at the clamped rate for the rest of the file. A connection whose rate falls below half of its own starting rate is now replaced, from the exact byte it had reached. Finishes on that server shape measure 2.3 times faster; steady connections are never touched.
  4. A click in the browser lands sooner. The hand-off from the extension to the running app polls at shorter intervals on both sides of the native host, and the short wait before a Facebook probe now applies to YouTube only. A start that modelled at roughly 240 milliseconds now models at roughly 85 — about three times quicker from click to first byte.
  5. The browser’s own identity travels with a capture. Downloads started from the browser used to present one fixed user agent, whatever browser sent them; they now present the capturing browser’s real one, alongside its cookies, so a session-bound server treats the download as the same visitor it served the page to.
  6. The end of a download wastes less time. The last blocks of a file can split toward idle connections when one connection straggles; when the audio side of a video finishes, its connections join the video side instead of idling; and a merge whose audio is already AAC no longer re-encodes it — the silent nine seconds or so after a video’s last byte are now under a second.
  7. And the fixes: pausing during a video’s stall recovery is honoured — the download no longer restarts itself behind a “paused” label; a redirect loop can no longer arrive disguised as a finished, empty file; very long file names are capped within filesystem limits in every case; the Finished progress dialog’s Cancel button closes it, as it always should have; and the Debian package declares the SVG icon library its toolbar needs, so a minimal system no longer loses the icons in silence.

A note on proof: this release was exercised the way it is used, on the shipped .deb — the main window pictured on this page is that build. An update check against the live feed read “up to date”; a public file matched its published hash exactly; a full Debian ISO was paused at 86%, resumed, and finished byte-identical with Debian’s published SHA-256; and a video file completed. The self-healing was proven separately, on a rig that expires signed links in the middle of a download. It also passed all four CI builds: Linux, both Windows architectures’ test suites, and a silent install-and-launch check of the universal setup.

A few things worth knowing.

Clear answers before you install.

Is NDM free?

Yes. NDM is free and open source under MIT OR Apache-2.0. There is no paid tier, account, or feature locked behind sign-in.

Which systems are supported?

Windows 7 SP1, 8, 8.1, 10, and 11 in 32-bit and 64-bit. The universal installer selects the matching build. Linux support is for x86-64 Debian-family distributions, through the .deb or portable tarball.

Is the browser extension a separate app?

No. The optional Chrome and Firefox extension sends browser downloads to the installed NDM desktop app. You can also paste a URL or use the drop basket without the extension.

What information leaves my machine?

Your downloads go to the servers you choose. NDM checks its release feed and sends one anonymous install-count request with no identifier attached. There is no telemetry and no sign-in.
