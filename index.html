Nill Download Manager

A free download manager for Windows and Linux. Files are fetched over parallel connections and written in place; an interrupted download resumes from the recorded byte after a restart. Video pages are handled by yt-dlp, through a browser extension and an in-page quality picker. The app updates itself.

System requirements

Windows

  • Windows 7 SP1, 8, 8.1, 10 or 11, 64-bit (x86-64).
  • The installer runs per-user; no administrator rights are required and nothing is installed system-wide.
  • On Windows 7 SP1, 8 and 8.1, the installer also provisions the WebView2 runtime in the background during setup: Microsoft's pinned 109.0.1518.78 build, checked against its SHA-256 hash before it runs. There is nothing to click, and the app carries its C runtime with it, so no separate redistributable install is needed on any supported Windows.
  • The installer is the app alone. On first launch, the video components (yt-dlp, deno and ffmpeg) are downloaded once, in the background, into the app-data folder. Each file is checked against a SHA-256 hash pinned in the app before it is allowed to run; a file that fails the check is deleted.

Linux

  • 64-bit Debian-family distribution: Debian, Ubuntu, Zorin OS, Linux Mint and derivatives.
  • The .deb declares its dependencies — libwebkit2gtk-4.1-0, libgtk-3-0 and ffmpeg — and apt installs them with the package.
  • On first use, the video components (yt-dlp and deno, about 83 MB) are downloaded once into the app-data folder. Each file is checked against a SHA-256 hash pinned in the app before it is allowed to run; a file that fails the check is deleted.

NDM installs no background services and starts nothing at boot. The extension needs the desktop app installed: it passes links through a small bridge process that the browser starts on demand.

Install

Windows

  1. Download NDM_2.0.10_x64-setup.exe from the table above and run it.
  2. The installer is per-user: there is no administrator prompt. It also registers the browser bridge (a native messaging host), so the extension can reach the app without any manual setup.
  3. Launch NDM from the Start menu. Uninstall works the usual way, through Windows Settings → Apps.

Portable build: extract NDM_2.0.10_Windows_Portable.zip to any folder and run the app from there.

Linux (.deb)

  1. Download NDM_2.0.10_amd64.deb from the table above.
  2. Install it with apt so the dependencies come with it: sudo apt install ./NDM_2.0.10_amd64.deb
  3. Launch NDM from the applications menu. The portable tarball needs no install: extract it and run the app; it carries the video components with it.

Browser extension

  1. Download ndm-extension-2.0.10.zip and unzip it. The desktop app must be installed first — the extension passes links to it through the native messaging host.
  2. Chromium browsers (Chrome, Brave, Edge): open chrome://extensions, enable Developer mode, click Load unpacked and select the unzipped folder.
  3. Firefox: open about:debugging#/runtime/this-firefox, click Load Temporary Add-on and select the manifest.json inside the unzipped folder. Firefox drops temporary add-ons when it restarts, so reload it the same way after a restart.

Features

Parallel connections, written in place

Each download opens up to 32 connections — 8 by default — and writes 1 MiB blocks directly at their final offsets in the target file. There are no part files and no merge pass at the end: when the progress reaches 100%, the file is already whole. Hosts that throttle parallel connections can be assigned a lower per-server limit, by exact hostname or wildcard pattern.

Resume, kept in a journal

Progress is written to a journal file (downloads.json in the app-data folder) as it happens, not at exit. Restart the app or the machine and every unfinished entry resumes from its recorded offset, as long as the server answers Range requests. If a signed link has expired in the meantime, paste the fresh link onto the same entry and the download continues instead of starting over.

Video downloads via yt-dlp

Video pages are resolved by yt-dlp (release 2026.10.26) with deno 2.9.8 as its JavaScript runtime — YouTube, Facebook, and the other 1,700+ sites yt-dlp supports; NDM does not parse those sites itself. The picker lists every available format with its real size before anything is downloaded. Selection prefers MP4/H.264, and where a site serves audio and video as separate tracks, ffmpeg merges them.

Browser extension

The extension for Chromium browsers and Firefox hands downloads and video pages to the app over a native messaging host. For a link behind a login, it captures the browser's cookies for that link only; they are stored as a file tied to that entry in the app-data folder and sent with that download's requests. While a download runs, a card on the page shows its percent and rate, with pause, resume and the speed limiter.

Speed limits and a quota

There is a global speed limit in Options and a separate one per download in its detail window, both set in MB/s. A limit applies to a running download as soon as it is set, from the app or from the browser card, and is remembered across restarts. An optional quota caps the total megabytes downloaded per period — the period is set in hours, from 1 to 168 — and when the cap is reached, new downloads wait until the window rolls over.

Queues and scheduler

Downloads belong to named queues. The cap on simultaneous downloads applies per queue; a queue can be set to start and stop at fixed times of day, and when a queue finishes it can leave the app running, exit the app, or shut the machine down.

Categories

Each category has an extension list and a folder, and a download is saved into the folder of the category its extension matches: Compressed, Documents, Music, Programs, Video, plus any categories you add yourself. A new download never overwrites a finished file with the same target name — a collision is given its own name instead.

Getting links in

Add URL accepts one link or a pasted list. Links and files can be dragged into the main window or onto the drop basket, a small always-on-top window. The Site Grabber takes a page URL, lists every file linked from that page filtered by type, and downloads the selection in one go.

Self-update

Twelve seconds after launch, and then every six hours while the app runs, NDM fetches a small JSON feed published alongside each release and compares version numbers. An offered update is downloaded, its SHA-256 checked against the feed, and only then installed. The feed also sets a minimum supported version: below it, the app opens but pauses new downloads until the update is installed. A manual check (Help → Check for Updates) leaves its result on screen until you dismiss it.

Themes

The default theme is the light glass finish used in the screenshots below. A dark theme with the same layout, columns and density is one click away in the toolbar.

2.0.102 November 2026
  • Required update: installs older than 2.0.10 are asked to update once, and new downloads stay paused until it is installed. As before, the prompt changes nothing — the list and any partial files are exactly as they were.
  • "Download Later" no longer loses the download. Choosing Download Later on a browser download dropped the folder, the timing and the total size on the way to the app; the app then opened its add dialog anyway, the browser card said "Queued in NDM", and closing that dialog threw the download away entirely. The choices now travel with the download through the extension and the native host, and a "later" download is queued as one — nothing depends on a dialog staying open.
  • The extension-update notice can be trusted again. The app only learned the extension's version when the extension happened to check in, so a user who only ever downloaded could run an out-of-date extension without ever being told. The version now rides along with the extension's download messages as well, and a version stamp old enough to be meaningless is ignored instead of suppressing the notice forever.
  • Cancel means cancelled. The download card used to declare "Cancelled" whether or not the app had actually accepted the cancel — it never looked at the answer. It now waits for the app's reply: if a cancel does not go through, the card restores its buttons, shows what went wrong and keeps watching, instead of reporting a success that never happened.
  • An interrupted merge can no longer pass as finished. If the power died while a video's parts were being merged, the restored entry could be marked Finished on the file's length alone, with no check of the contents. A download that was mid-merge now comes back as paused, and its file is verified when it resumes instead of being trusted on arrival.
  • Deleting waits for the engine to stop, and Pause All reaches everything. Removing a download gave the engine five seconds to settle and then swept the files regardless, even though the engine can legitimately take much longer to wind down; deletion now waits on the engine's real settle bound and refuses rather than racing a download that is still running. Pause All now also requeues downloads that are starting or merging — before, those were paused on screen and never restarted.
  • Videos start sooner. The format chosen in the picker was resolved a second time when the download actually started, and a slow or stuck resolver could hold the start up indefinitely. The chosen format is now warmed as it is picked, and resolving carries a 45-second bound — past it, the download falls back to the standard path instead of hanging.
  • Small truths, swept clean. When a download finishes, the rows in the progress dialog's per-connection table now read "Done" instead of sitting at "Waiting…" forever; and the zero-byte .ndm.lock files that finished downloads used to leave behind in the download folder are now swept away once nothing holds them.
  • A failed portable update hands the app back. If a portable update fails partway and the previous version is restored, the restored copy now relaunches itself and leaves a note of the failure for the next start, instead of leaving the user with nothing running and no explanation.

FAQ

Is NDM free?

Yes. There is no paid tier, no advertising and no account. The files in the downloads table are the whole product.

Why is the Windows installer only about 4.3 MB?

It carries the app alone — the same arrangement as the Linux .deb (5.30 MB). The video components (yt-dlp, deno, ffmpeg) are downloaded once, in the background on first launch, and each is verified against a SHA-256 hash pinned in the app before it is allowed to run; on Linux, ffmpeg also arrives as an ordinary package dependency of the .deb. One exception in the table: the Linux portable tarball (122 MB) still bundles the components, so it runs with nothing installed. The Windows portable is application-only, like its installer. On Windows 7 SP1, 8 and 8.1 the installer also provisions the WebView2 runtime in the background during setup, verified the same way before it runs.

What data leaves my machine?

Three things. Your downloads, obviously. The update check: a small JSON file fetched 12 seconds after launch and every six hours after that. And one anonymous install count — an empty GET request to a public counter service (abacus.jasoncameron.dev), sent once per major version, carrying no identifier, no file names and no URLs; it exists so the install total is a measured number instead of a guess. Download history, saved site logins and per-entry cookie files stay in the app-data folder on your own disk.

Does resume really work after a restart?

Yes, with one condition that is the server's, not NDM's: the server must answer HTTP Range requests. Most file hosts do. Progress is journaled continuously, so after a pause, a crash or a full restart the entry picks up at the recorded byte. If a server ignores Range requests, that download starts from zero — no client can resume against a server that refuses to serve partial content.

Which browsers does the extension support?

Chrome, Brave, Edge and other Chromium browsers, and Firefox. The desktop app must be installed, because the extension reaches it through a native messaging host. In Firefox the extension runs as a temporary add-on (see the install steps), so it has to be reloaded after the browser restarts.

Can I use NDM without the extension?

Yes. Paste links with Add URL, drag links or files into the main window or onto the drop basket, or point the Site Grabber at a page and take the files it lists. The extension only automates catching downloads and video pages while you browse.

How do updates install — and can one be forced?

When the feed offers a newer version, the app downloads the package, verifies its SHA-256 against the feed, and only then hands it to the installer. The feed also names a minimum supported version. If your copy is older than that floor, the app still opens and your list is intact, but new downloads pause until the update is installed — that path exists so a critical fix cannot be postponed forever.
