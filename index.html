Check what you received

Each file’s SHA-256 is printed beside it, exactly as published with the release. Compare the hash of the file you received before you run it:

Get-FileHash .\NDM_2.3.2_setup.exe -Algorithm SHA256

The Windows setup is a single file for both architectures: it carries the 64-bit and the 32-bit build and installs the one your machine needs, so there is no wrong setup to pick. The Linux portable is the large file in the table because the video components are bundled into it; every other file is the application alone.

What changed in 2.3.2

  • A download whose link expires in the middle no longer dies there. When the server answers a range with 403 or 410 — the signed address has lapsed — NDM re-resolves the address and resumes from the journal, for plain files and for browser-captured video alike. On the test rig, the two shapes that used to fail, at 44% and at 63%, now run to completion byte-identical. A paused download is never woken by the refresh, and if the file behind the link has changed, the entry restarts cleanly from zero instead of splicing two different files together.
  • Facebook’s picker is instant now, finishing what the last release started. A video on Facebook fills the picker from the page’s own data, the way YouTube already did — quality rows at once, on posts, watch pages and the feed, each video on a busy page offered on its own. A video the page cannot identify is reported plainly, instead of the picker probing the wrong address; and if Facebook changes its page structure, the picker falls back to the classic resolver on its own.
  • Connections that decay are recycled. Some servers hand each connection a fast burst and then clamp it to a trickle — the shape behind most “slower than the other manager” reports — and a download could sit at the clamped rate for the rest of the file. A connection whose rate falls below half of its own starting rate is now replaced, from the exact byte it had reached. Finishes on that server shape measure 2.3 times faster; steady connections are never touched.
  • A click in the browser lands sooner. The hand-off from the extension to the running app polls at shorter intervals on both sides of the native host, and the short wait before a Facebook probe now applies to YouTube only. A start that modelled at roughly 240 milliseconds now models at roughly 85 — about three times quicker from click to first byte.
  • The browser’s own identity travels with a capture. Downloads started from the browser used to present one fixed user agent, whatever browser sent them; they now present the capturing browser’s real one, alongside its cookies, so a session-bound server treats the download as the same visitor it served the page to.
  • The end of a download wastes less time. The last blocks of a file can split toward idle connections when one connection straggles; when the audio side of a video finishes, its connections join the video side instead of idling; and a merge whose audio is already AAC no longer re-encodes it — the silent nine seconds or so after a video’s last byte are now under a second.
  • And the fixes: pausing during a video’s stall recovery is honoured — the download no longer restarts itself behind a “paused” label; a redirect loop can no longer arrive disguised as a finished, empty file; very long file names are capped within filesystem limits in every case; the Finished progress dialog’s Cancel button closes it, as it always should have; and the Debian package declares the SVG icon library its toolbar needs, so a minimal system no longer loses the icons in silence.

A note on proof: this release was exercised the way it is used, on the shipped .deb — the main window pictured on this page is that build. An update check against the live feed read “up to date”; a public file matched its published hash exactly; a full Debian ISO was paused at 86%, resumed, and finished byte-identical with Debian’s published SHA-256; and a video file completed. The self-healing was proven separately, on a rig that expires signed links in the middle of a download. It also passed all four CI builds: Linux, both Windows architectures’ test suites, and a silent install-and-launch check of the universal setup.

What changed in 2.3.1

  • Video started from the browser is browser-first now. The picker takes the page’s own stream data — the formats the browser already loaded — so it fills at once, and the file comes down through the multi-connection engine. yt-dlp remains, as the fallback for pasted links and for pages that expose nothing usable.
  • A start could sit for some 27 seconds before the first byte. The cookie signature was computed two different ways on the two sides of a start, so the probe the picker had just paid for never matched the job that followed it; every start probed from scratch. Both sides sign the same way now, and a start reuses the probe it already has.
  • When a video stream stalls, only its address is refreshed and the download resumes from the byte it had reached — the status reads “Resuming…” — instead of probing the page again from the top.
  • Pause and resume work in every state, including while a video is still connecting, and the progress window’s buttons follow the state the download is actually in; its transfer rate and time left stay live while data moves.
  • Facebook’s picker can no longer spin without end: it stops at 20 seconds with a plain message, feed links are normalized before they are resolved, and the file takes the post’s text as its name instead of the word “Facebook”. Facebook’s instant page-data picker is still being finished.
  • A video that never finished connecting could not be deleted from the list at all — its entry pointed at the folder itself, and every delete failed on it. Entries are always removable now; a file that genuinely cannot be deleted is reported, and the entry can still be cleared. A full disk likewise stops a download at once, with a clear sentence, instead of retrying the same blocks in silence for minutes.
  • The browser extension’s file dialog is the video picker’s glass card — file name, folder, size and resume support, three actions: Download Now, Download Later, Cancel. The old plain form is gone everywhere.
  • A drawn icon set now covers the toolbar, the menus and the file rows, and the finish is calmer: softer button states and a visible focus ring. The View menu’s Dark Theme and Categories Sidebar switches were found wired to nothing; they work now, and the choice is remembered.
  • Downloads taken by the updater arrive under their real file names instead of temporary ones, and the “Download complete” dialog wraps its text and stays inside the screen.

A note on proof: this release was exercised the way it is used — the shipped .deb, the extension installed in a real browser handing a download to the app end to end, a full Debian ISO matched against Debian’s published SHA-256, a pause and resume in the middle of it, and an update check against the live feed. It also passed all four CI builds: Linux, both Windows architectures’ test suites, and a silent install-and-launch check of the universal setup. On Windows, list sorting and the glass download card are still to come, and the Windows toolbar keeps its text buttons in this release.

How it runs

Take the file for your system.

One setup installs the right Windows build, 64-bit or 32-bit; the .deb covers the Debian family, and the portable files run as they are. Every file above is published with its SHA-256.

Add a link, from anywhere.

Paste a URL, drop a file on the basket, or let the browser extension hand the download over, with that link’s cookies attached to the entry.

It pulls the file down in parallel.

Up to 32 connections write 1 MiB blocks at their final offsets, and a journal records the progress as it happens. The strip in the dialog is the file, filling in place.

At 100%, it is already whole.

No part files and no merge pass, because the file was written in place. Stop it at any point and it resumes from the recorded byte; a finished file is never overwritten.

The main window, as it opens.

The engine

An engine that expects interruption.

Resume is a journal, not a hope

Progress is written to downloads.json as it happens. Restart the app or the machine, or let a signed link expire: the entry keeps its bytes, and Refresh Address attaches a fresh link to the same entry.

A limiter on each download

Set a rate for one file while it runs, or a global cap with a quota in megabytes over 1 to 168 hours. The change applies mid-flight, not at the next start.

Queues that keep hours

Named queues carry their own concurrency caps and start and stop times. When a queue runs dry it can close the app, or shut the machine down.

Whole sites in one go

Site Grabber walks a page and takes every linked file of the types you choose. Categories then route each finished file into its folder by extension, and the drop basket takes drags from anywhere.

Updates that check themselves

NDM reads its own release feed, verifies the SHA-256 of an update before installing it, and honours the feed’s minimum supported version — the 2.0.10 feed used it to require that update.

Questions

Is NDM really free?

Yes, and open source. There is no paid tier, no account and nothing locked behind one. The files in the release above are the whole product.

Why is the installer only 6.27 MB?

It carries both Windows builds of the app and nothing else: one Rust engine serves both platforms, and the app brings its C runtime with it. The video components (yt-dlp, deno and ffmpeg) are downloaded once, in the background, the first time a video is resolved, and each is checked against a SHA-256 pinned in the app before it may run.

Which systems does it run on?

Windows 7 SP1, 8, 8.1, 10 and 11, in 64-bit and 32-bit — the one installer picks the build that matches the machine. On Linux, a Debian-family distribution on x86-64 (Debian, Ubuntu, Zorin OS, Linux Mint and derivatives), through the .deb or the portable tarball.

What leaves my machine?

Your downloads, from the servers you pick. An update check against the release feed. And one anonymous install count, an empty request with no identifier attached. There is no telemetry and no sign-in.

A download stopped at 99%. Is it lost?

No. Progress lives in the journal, not in temporary part files, because there are no part files. Resume continues from the recorded byte. If the link itself has expired, Refresh Address attaches a fresh signed link to the same entry, and an interrupted merge restores as paused and is verified before it can count as finished.

Do I need the browser extension?

No. Paste a link, or drag one onto the drop basket. The extension, for Chrome and Firefox, only removes the copy and paste: it sends the browser’s downloads to the app, carrying the cookies for that link, which are stored with that entry only.

Windows, or Linux — take release 2.3.2 as the Windows setup or the Linux .deb, and the browser extension with either.

Either way it is served from the release feed, and the hashes in the table above are how you check what arrived.
